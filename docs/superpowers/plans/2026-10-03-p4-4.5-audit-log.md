# Krok 4.5: Audyt tylko do dopisywania i endpoint listy z filtrami — plan

> **Dla agentów:** WYMAGANY SUB-SKILL: `superpowers:subagent-driven-development` (zalecany) lub `superpowers:executing-plans`. Kroki używają checkboxów (`- [ ]`).

**Cel:** Jedna droga zapisu do `audit_logs` dla całego zespołu, gwarancja append-only w bazie, wspólna infrastruktura API v1 i `GET /api/v1/audit` z filtrami.

**Architektura:** `app/services/audit_service.py` udostępnia tylko zapis (`write_audit_event`) i odczyt (`list_audit_entries`). Migracja Alembic `0002` zakłada wyzwalacze SQLite blokujące `UPDATE`/`DELETE`. Infrastruktura API v1 to `deps.py`, `errors.py` i `router.py`: `ServiceError` zamienia się w `{"detail": ...}`, a `v1_router` ma prefiks `/api/v1`. Odpowiedź `AuditEntry` zawiera gotowy `actor_login`.

**Stack:** FastAPI, SQLAlchemy 2.0 async, Alembic, pytest-asyncio.

**Spec:** ADR 0010 §2, §4, §5.7–5.8; ADR 0007 pkt 5 i 9; ADR 0009; `PRODUKT.md` M6.

**Branch:** `feat/4-5-audit-log` · **Commit:** `6b51461` · **Zależności:** `main` (1.1–1.6) · **Odblokowuje:** wszystkie pozostałe kroki 4.x, 2.5 (audyt time-travel), 3.6 (audyt decyzji), 5.10

## Ograniczenia globalne

- `audit_logs` powstają wyłącznie w `write_audit_event`, który tylko robi `flush`; `commit` należy do routera.
- `actor_id` = `users.id`; aktor `ADMIN` = `Settings.admin_login` (od 4.2), `SYSTEM` = `None`.
- `action` w bazie to tekst, ale zapis przyjmuje wyłącznie `AuditAction`.
- Sortowanie `timestamp DESC, id DESC`; `limit` 1–1000 (domyślnie 200); `target` to fragment bez rozróżniania wielkości liter, a `%`/`_` są dosłowne.

## Review Focus

- **Surowy SQL omija ORM** → `test_audit_logs_reject_raw_update_and_delete`.
- **Reset demo (`downgrade base` → `upgrade head`) przy wyzwalaczach** → `test_demo_reset_still_rebuilds_schema` oraz smoke `POST /api/v1/demo/reset`.
