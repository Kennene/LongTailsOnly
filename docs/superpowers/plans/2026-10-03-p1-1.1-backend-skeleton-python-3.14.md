## Global Constraints

- Python `>=3.14` (`requires-python = ">=3.14"`, `.python-version` = `3.14`).
- Zależności runtime: `fastapi`, `uvicorn[standard]`, `sqlalchemy[asyncio]`, `aiosqlite`, `pydantic`, `pydantic-settings`.
- Zależności dev: `pytest`, `pytest-asyncio`, `httpx`.
- Każda funkcja ma type hints; plik ≤ 300 linii.
- **Nie commitujemy, nie pushujemy, nie otwieramy PR** — kończymy na `git add`, commit robi Kocik.

## Review Focus

1. Ktoś ma aktywne `.venv` z katalogu głównego repo → `uv` ostrzega `VIRTUAL_ENV ... does not match` i może użyć złego Pythona; oczekiwane: polecenia uruchamiane z `backend/` przez `uv run` używają `backend/.venv` z 3.14.
2. Kolega bez `uv` robi `pip install -e '.[dev]'` → oczekiwane: instalacja przechodzi (stąd `build-system` + `optional-dependencies`).
3. Ktoś ma Pythona < 3.14 → `uv sync` ma zgłosić czytelny błąd wersji, nie cicho użyć starszej.

### Task 1: Test konfiguracji projektu + przejście na 3.14

**Files:**
- Create: `backend/tests/__init__.py` (pusty)
- Create: `backend/tests/test_project_setup.py`
- Modify: `backend/pyproject.toml`
- Modify: `backend/.python-version`
- Modify: `backend/README.md`

**Interfaces:**
- Consumes: istniejący `app.main:app`, `tests/test_health.py`.
- Produces: `pyproject.toml` z extra `dev`; polecenie `uv sync --extra dev` dla zespołu.

- [ ] **Step 1: Napisz test, który pada**

`backend/tests/test_project_setup.py` (klasa `unittest.TestCase`, żeby działała i pod `unittest`, jak w planie zespołu, i pod `pytest`):

```python
import tomllib
import unittest
from pathlib import Path

PYPROJECT = Path(__file__).resolve().parents[1] / "pyproject.toml"


class ProjectSetupTest(unittest.TestCase):
    def test_pyproject_declares_backend_dependencies_and_pytest(self) -> None:
        data = tomllib.loads(PYPROJECT.read_text(encoding="utf-8"))
        project = data["project"]

        self.assertEqual(project["requires-python"], ">=3.14")

        runtime = " ".join(project["dependencies"])
        for name in ("fastapi", "uvicorn", "sqlalchemy", "aiosqlite", "pydantic"):
            self.assertIn(name, runtime)

        dev = " ".join(project["optional-dependencies"]["dev"])
        for name in ("pytest", "pytest-asyncio", "httpx"):
            self.assertIn(name, dev)

        self.assertIn("pytest", data["tool"])
        self.assertIn("build-system", data)
```

- [ ] **Step 2: Uruchom test — ma paść**

Run (z `backend/`): `uv run python -m unittest tests/test_project_setup.py -v`
Expected: FAIL — `AssertionError: '>=3.12' != '>=3.14'`.

- [ ] **Step 3: Przenieś zależności dev do extra `dev`**

```bash
cd backend
uv remove --dev pytest pytest-asyncio httpx
uv add --optional dev pytest pytest-asyncio httpx
uv add pydantic
```

- [ ] **Step 4: Ustaw Pythona 3.14 i build-system**

```bash
uv python pin 3.14
```

W `backend/pyproject.toml` ustaw `requires-python = ">=3.14"`, popraw `description` i dopisz na końcu:

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["app"]
```

- [ ] **Step 5: Odtwórz środowisko na 3.14**

Run: `uv sync --extra dev && uv run python --version`
Expected: `Python 3.14.x`.

- [ ] **Step 6: Uruchom testy — mają przejść**

Run: `uv run python -m unittest tests/test_project_setup.py -v && uv run pytest -q`
Expected: test konfiguracji `OK`; pytest `2 passed`.

- [ ] **Step 7: Sprawdź ścieżkę bez uv (jak w planie zespołu)**

Run (w osobnym, tymczasowym venv): `py -3.14 -m venv %TEMP%\lt-venv && %TEMP%\lt-venv\Scripts\python -m pip install -e ".[dev]"`
Expected: `Successfully installed ... longtails-backend`.

- [ ] **Step 8: README**

W `backend/README.md` zamień `uv sync` na `uv sync --extra dev`, dopisz „Wymagany Python 3.14” i alternatywę `pip install -e '.[dev]'`.
